04 / 10Architecture

Why the Shared Pool Is 2W1R

Two arrivals must never be rejected

write 0 · E write 1 · W single shared read
2W
E and W may deposit in the same cycle
1R
one pooled flit drains per pair per cycle

Input links are credit-controlled but an arriving flit cannot be sent back. Two write paths preserve lossless simultaneous arrival; one read port is shared by an E/W request arbiter.

Read-side trade

Two private input banks may drain independently. The Pool exposes only one shared read, so E and W contend when both have ready pooled flits.

Capacity-side gain

The hot side can occupy slots that would be stranded behind the opposite input's private wall. Under one-sided demand, the shared read is not a bottleneck.

Honest hardware boundary

2W1R is an implementation assumption, not a free resource. SRAM/register-file area, write-port energy, central wiring and read arbitration must be measured separately from gem5.

05 / 10Implementation

Pool-Credit Grant: Demand-Aware STARVE vs. Blind RR

Credit meaning

Each free Pool slot has exactly one upstream owner. Holding its credit means that side may place one adaptive packet into the shared storage.

STARVE rule

On a Pool release, grant the credit to a side with no usable free Pool credit. If both sides are equally eligible, use round-robin.

Reserved credit

One private adaptive VC and one escape VC remain outside the Pool. Escape capacity never migrates, so safety does not depend on the grant policy.

Credit Return: Recover Stranded Ownership Without Revocation

Release-only grants can freeze

If West is idle, its Pool slots do not release—and therefore generate no event that could move ownership to hot East. The need for migration rises exactly when release traffic disappears.

The owner returns voluntarily; the router never revokes a credit that may already be promised to an in-flight flit.

Garnet Mapping and Current Repository Status

Datapath placement

  • Pool is indexed by the packet's true input direction pair—not by its next output.
  • A West-in packet can occupy the E/W Pool and leave through North: X-in → Y-out remains legal.
  • Escape traffic maps only to the private reserved region.

Safety contracts

  • g_E + g_W = P: no Pool credit is created or lost.
  • One free slot has one owner; ownership may move only while the slot is safe to grant.
  • Reserved escape capacity is physically excluded from migration.
  • 2W accepts both directional arrivals; 1R arbitration serializes Pool drain.

Takeaway: The Deck Is Ready; the 2W1R Result Is Not Yet

Clear story

Architecture → implementation → evaluation, with no mixed-generation evidence.

  • Architecture: three opposing-port pools per router; RES protects private adaptive + escape capacity.
  • Datapath: 2W accepts simultaneous paired arrivals; 1R serializes pooled drain.
  • Policy: STARVE directs released credits toward demand; surplus return recovers parked ownership.
  • Control evidence: 1,700 older runs prove counter-only sharing cannot create a physical benefit.
  • Open evidence: the 1,400-run 2W1R matrix must still be executed.
1 · implement

Land dynamic owner state, 2W write acceptance, 1R arbitration, and the voluntary return flag on the current clean design branch.

2 · validate

Run purity anchors and directed simultaneous E/W arrival tests before trusting performance data.

3 · evaluate

Execute the 1,400-run matrix, then add burst length and owner-return threshold sensitivity.

Do not claim a 2W1R speedup yet. The current slide deck presents a testable design and an honest evidence boundary.
