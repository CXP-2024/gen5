## 1. 机制

固定一个路由器和一个维度，取对向输入端口对 `{E-in, W-in}`（N/S 对、第三维
上下对同理）。基线布局：每侧 `v` 条 VC、每 VC 深度 1（ctrl vnet 0 是 1-flit
包），故**一个槽就是一个 VC 表项**，每侧 `v` 个槽，`B_pair = 2v`。

**槽的三分**（总量与基线逐槽相等，`B_pair = 2r + P` 不变）：

| 类别 | 数量 | 物理位置 | 所有权 |
|---|---|---|---|
| 保留区 | 每侧 `r` | 本侧 IU | **永久属本侧**，含逃逸 VC |
| 共享池 | 共 `P`（每 IU 各 `P/2`） | 分布在两个 IU | **可在两上游间迁移** |

**共享的定义 = 使用权迁移，不是新建一块共享阵列。** 池槽物理上仍是某个 IU
的 VC 表项；R 可以把 W-IU 中某个池 VC 的**使用权**授予 E，此后 E 的 flit
写进 W-IU 的该表项，并在 **W 的 SA-I 里与 W 自己的 flit 一起 round-robin**。

**新颖点压缩成一句**：

> **传统 credit 语义逐字保留——单枚 credit 即充分可发、无双钥匙门、无超售；
> 唯一的改变是池 VC 的所有权会随时间在两个上游之间迁移。**

上游看到的就是"我当前拥有一组可用 VC id，往其中任一个发，有 credit 就发"，
**不区分 credit 类型**。类型区别只存在于 R 的授予器内部：保留 VC id 永久归
本侧，池 VC id 在释放时被重新决定给谁。

**用户表述的机械化**："E 来的包多了，W 的 VC 被堵住"——E 借走池 VC 后，W 的
可用 id 集合真实缩小，可用容量随 E 的借用量实时缩水。这是对真实存储的争用，
不是记账假象。

## 2. 形式定义

**定义 1（所有权）**：`g_f(t)` = 当前授予给 `f` 侧的池 VC 数。
**不变式 OWN**：`g_E(t) + g_W(t) = P`（`U ≈ 0`，见 §4.1——扣在 R 手里的
credit 两侧都用不上，是纯浪费）。

**定义 2（动态落地上限）**：

```
H_f(t) = r + g_f(t)      ∈ [r, r+P]
```

私有基线是常数 `H_f = r + P/2`——阶段2 Corollary 1 证明任何计数器都推不动
这个量。**变体A 靠授予策略推动它**：`H_f` 完全由 `g_f` 决定，而 `g_f` 是授予
策略的输出。**机制 = 策略**，硬件只是让非平凡策略可表达（§4）。

**定义 3（cap）**：`c ∈ [⌈P/2⌉, P]`，强制 `g_f ≤ c`（对**所有权**设限，
不是对占用）。`c = P` 无治理；`c = P/2` 冻结为静态划分。

**定义 4（floor）**：`floor_f(c) = r + (P − c)`——对向借到顶时 `f` 仍保有的
容量。阶段1/2 的 cap 管的是没有实体的计数器；这里同一套纪律管真实槽位，防的
是经典 DAMQ 饥饿。**cap 第一次有了能赢的岗位**。

**定义 5（死锁基座隔离）**：逃逸 VC（routing 4）**永久属本侧保留区，绝不
进入可迁移集合**。逃逸网络的前向进展只依赖本侧保留区，与 `g_f`、与对向占用
完全无关：**基线的死锁自由证明逐字迁移**。

**推论（策略自由）**：正确性完全由保留区兜底 ⇒ 池的授予策略再激进、再不公平，
最坏也只是性能与公平性问题，**绝不威胁正确性**。策略设计因此从"必须证明无
死锁"降级为"调性能"——这是 `r/P` 分界买到的实际红利。

**注（服务带宽也被共享）**：E 借走的池槽由 **W 的读口**发出，故共享的不止
存储，还有服务带宽。W 闲时这是白捡的（W 读口本就空转）；W 忙时 E 本也借不到，
自限。副作用：E 借用期间可在同周期从 E-IU 和 W-IU 各发一个 flit，**瞬时服务
率超过 1 flit/周期**。因此测得效应是"**存储 + 服务**"，不是纯槽效应——§8 的
三阶段分解须按此口径声明。

## 3. 成立条件（何时有收益）

**C1（缓冲为瓶颈）**：`BDP ≈ RTT_credit × BW_link > r + P/2`。
抬高上限只有在缓冲本身限制吞吐时才变成吞吐。C1 不满足时两种配置都饱和在
链路/路由极限上，预测**平局**。默认 1 周期链路下 BDP ≈ 2–3 ≤ r+P/2 = 4：
只在默认链路跑实验会**按构造复现零结果**——正是阶段2 揭示的那类陷阱。实验
必须用长链路制造 C1（§7），而长链路同时就是诚实的应用域：chiplet / D2D、
片上长互连——credit RTT 随距离和 SerDes 延迟增长、每 lane 缓冲面积金贵，与
许可域模型（`permission_domain/` §3）的 PS1 域重合。

**C2（对内需求不对称）**：只有对向闲时才有槽可借。tornado 类流量加热一个
方向、闲置对向，是结构性 C2；xopposite 双向皆热，是结构性 ¬C2。

**`P` 的双向对冲（实验必须扫描的理由）**：

- `P` 小 → C1 门槛 `r + P/2` 低 → **适用窗口更宽**；
- `P` 小 → 天花板比 `(r+P)/(r+P/2)` 低（`r=1,P=2` 仅 1.5×，`r=1,P=6` 为
  1.75×）→ **收益上界更低**；滞后阈值只能是很小的整数，策略粒度粗。

两个方向相反，最优点在中间——这个 trade-off 本身就是一条结论。

**结论：收益 ⟺ C1 ∧ C2；侵占暴露 ⟺ C1 ∧ ¬C2。** 两句都可证伪，实验矩阵在
两侧都布了格子。

## 4. 授予策略（本设计的贡献所在）

### 4.1 释放时授予：`U ≈ 0`，中间人是一根线不是一个寄存器

**扣在 R 手里的池 credit 对应一个谁都填不了的空槽**——E 没权限、W 也没权限。
`P` 本就小，扣 1 枚就砍掉一大块可用容量。所以**不设蓄水池**：

```
ST 周期：flit 离开池槽（R 内部事件，0 跳，R 本周期即知）
        ↓  同周期，R 立即按策略决定 target ∈ {E, W}
     授予信号发出（1 跳）
```

credit 在 R 手里停留 **0 周期**。**发送 = 释放 = 授予，同一周期、同一事件、
同一处代码。** 而"释放→再供给"的路径长度是 **1 跳，与传统 credit return
完全相同**——传统 credit 也要付这 1 跳。**正常路径上没有任何额外延迟。**

**安全性自动成立**：R 只针对**已确实腾空的槽**发 credit，超额承诺在构造上
不可能发生。故 v1 草案里的 `P_eff = P−1` 陈旧性准备金（蓄水池模型的产物）
**撤回，不需要**。

**Δ 的准确定义**：Δ = 授予环路**相对于传统 credit return 的额外延迟**。正常
路径 Δ=0 是物理事实，不是理想化。Δ=0 真正理想化掉的只有**改派**（§4.3）。

### 4.2 策略阶梯：传统 credit 就是最平凡的那个策略

| 策略 | `target(释放事件)` | 等价于 | 角色 |
|---|---|---|---|
| **RTS**（return-to-sender） | 给刚腾空那个 flit 的来源侧 | **私有基线，逐周期恒等** | 纯度锚点 / 零假设 |
| **RR**（round-robin） | 两侧交替 | 静态 50/50 划分 | 平凡共享对照组 |
| **STARVE**（本设计） | 见 §4.3 | —— | **贡献** |

第一行是**恒等式不是类比**：RTS 下所有权永不迁移，`g_f ≡ P/2` 恒定，
`H_f ≡ r + P/2` = 私有基线。**同一套硬件装上 RTS，行为与私有基线逐周期相同。**

这把整件事的性质定住了：**共享槽阵列本身不产生任何收益，它只是让 RTS 以外的
策略可表达；收益全部来自策略。** 声称面从"我们做了物理共享"（先行工作密集）
收窄为"**我们证明非平凡授予策略优于 return-to-sender**"——可证伪得多。
且三行是同一套硬件上的三个策略，**实验阶梯是纯软件的**。

### 4.3 STARVE 策略与自愿归还

**授予规则**（在释放事件上求值，状态**不含**刚腾空的那个槽）。令
`free_f` = `f` 当前拥有且空闲的槽数（含保留区）：

```
free_E == 0 ∧ free_W == 0  →  round-robin
free_E == 0                →  授予 E
free_W == 0                →  授予 W
两侧皆 > 0                 →  round-robin
```

**两处偏离用户原始表述，理由如下**：

1. **"都没空槽"档用 RR 而非随机**——① gem5 里随机需 RNG，会破坏 RTS≡PRIV
   纯度锚点的可复现性；② 硬件上 RR 是 1 bit 状态，随机是一个 LFSR。行为
   期望相同，成本与可验证性更优。
2. **补上"两侧皆有空槽"档**（原表述未覆盖）。此时授予不紧急，但 `U≈0` 要求
   credit 必须落地，故用 RR。

**自愿归还（voluntary return）**：`U≈0` 结构下唯一的真实漏洞是——"credit 在
R 手里没用"的同一理由说明"**credit 在一个没有流量的上游手里同样没用**"。
W 停发却攥着 3 枚，那 3 个槽就是 E 永远够不着的。

补丁方向是反的：**不要 R 去回收，让上游主动归还**——因为**只有 W 自己知道
W 有没有需求**。W 观察到"持有 credit > 自己排队的 flit"持续若干周期，就发
一个归还信号给 R，R 收下后立即按策略转授。

- **授予**：R → 上游，**1 跳，单向**
- **归还**：上游 → R，**1 跳，单向**

**两个方向都是 1 跳单向，没有 request-grant 往返。** 强制回收只作为永不触发的
安全阀存在，可不实现。**真实代价因此不是跳数而是滞后（hysteresis）整定**：
太急则需求一波动就来回搬运；太懒则漏洞留存。这是**瞬态代价，稳态不付**，
决定的是"划分跟随需求的响应速度"，不是稳态收益的高低。

**未决精化**：`free_f` 是否应排除逃逸 VC。一侧只剩逃逸槽空闲时按当前规则算
"不饥饿"，但逃逸是 DOR 受限的，实际接近饥饿。保留用户原规则，记为 §9-Q4。

## 5. 代价（全部明示）

### 5.1 端口代价：读口免费，写口要钱

**读口：零增量，且不是靠仲裁而是构造上不存在冲突。** 每个池槽物理上属于唯一
一个 IU，"谁能读它"静态确定——W-half 的槽只可能被 W 的 SA-I 选中。每个 IU
仍是每周期读 1 个 VC，**读口数量与基线逐字相同**。

> 对照：若池是独立于两端口的共享阵列（v1 草案的模型），两侧 SA-I 都可能同拍
> 选中池常驻 VC → 真需 2R。**分布式布局把这个问题消灭了**，代价转移到写口。
>
> 附带证伪一个诱人但错误的替代方案：**靠 RR 指针相位错开来避免争池端口是不
> 成立的**。`r=2,P=4` 时池占 6 个位置中的 4 个，每侧有 2/3 时间落在池上，
> 鸽笼原理给出重叠 ≥ 1/3，任何相位偏移都消不掉；更根本地，RR 只在非空且有
> 下游 credit 的 VC 中选，可选集由流量决定，相位不可控。升级成强制交替令牌
> 倒是能保证，但那把这一对的池读带宽钳死在 1 flit/周期（池占 8 槽中的 4
> 槽），重载下总吞吐从 2 掉向 1——**50% 带宽损失，收益全被淹没**。正确解就是
> 本节的静态槽→端口绑定：不靠指针在时间上错开（概率性、会失效），而靠槽在
> 空间上归属唯一端口（确定性、无例外）。

**写口：这是主要硬件代价，且牵涉无损性。** 每条链路每周期最多送 1 个 flit，
故这一对每周期最多 2 个到达。冲突条件被布局细化：

> **两个池 flit 同拍到达并不必然冲突——只有当它们落在同一个 IU 时才冲突。**
> `(E→E-half, W→W-half)` 各写各的 IU，无冲突；`(E→W-half, W→W-half)` 才撞。

（"每周期两个 reserve 或一个 reserve 一个 pool"对**整块池**模型成立；在分布式
布局下放宽为"同 IU 才冲突"。）

**但这不是性能问题而是正确性问题**：credit 流控**无拒收**，输的那个 flit
无处可去又不能丢。故必须有**保证**，不能靠临场仲裁。两条路：

- **(a) 池区双写口**（基线假设）：每 IU = 1W（本链路）+ 1W（跨接通路），
  读仍 1R。**保留区不受影响**（永不接收跨写），故 2W 只加在每 IU 的 `P/2`
  个池表项上，不是全部 `r + P/2` 个。
- **(b) 授予侧纪律**：策略保证不会出现同拍同 IU 双写。STARVE 天然罕见（借用
  发生在对向饥饿时，对向本就没在写），但"罕见"不是"保证"，**不足以承担
  无损性**。记为后续精化。

首批实验取 (a)，Δ=0 建模之，报告须声明。

**走线与时序**：跨接通路（E 的 flit 走到 W-IU 的写口）在路由器两侧之间穿行，
比私有缓冲的贴身走线长，高频下有时序压力
**[未验证: 与 Fukase 共享 SRAM 路由器同类问题]**。

### 5.2 干扰代价（C1 ∧ ¬C2 时的结构性暴露）

无治理（`c=P`）时对向可把池借空，`f` 的容量从 `r+P/2` 跌到 `r`——方向间吞吐
不公平与 matched-load 延迟退化是预期现象（经典 DAMQ hogging）。cap 是治理
旋钮，但**治理本身有价**：floor 每抬 1 槽，可借上限就降 1 槽（最大增益
= `c − P/2`）。`c = P/2` 是零退化零收益的中性点。增益与保护不可兼得。

**`r` 的内部划分是同一 trade-off 的具体形态**（`r` 拆成逃逸 + 自适应保留）：

- **`r = 1`（纯逃逸，无自适应保留）**：`P` 最大、天花板最高。风险实在：池被
  对向借空时本侧自适应容量归零，**全部流量被迫挤进逃逸 VC**——而逃逸是 DOR
  受限的，立刻成热点，性能塌方。
- **`r = 2`（1 逃逸 + 1 自适应保留）**：本侧永远保底 1 个自适应槽，退化平缓；
  代价是同 `B_pair` 下 `P` 少 2。

两点都进实验矩阵（§7）。

### 5.3 适用域与复杂度代价

- **窄适用域**：C1 在 1 周期链路的普通 mesh 里通常不成立——在那里部署此机制
  是**只付 5.1 的账、收益恒为零**。机制只该部署在长 credit 环或极小缓冲的
  场合，这是设计结论的一部分而非遗憾。
- **正确性负担**：私有缓冲的隔离是物理免费的；迁移后"逃逸槽永不进入可迁移
  集合"要靠分配逻辑保证（定义 5），验证面变大。
- **真实入口方向必须显式携带**（§6.3）：否则自适应路由可能允许 U-turn。

### 5.4 gem5 定位

5.1–5.3 的硬件项 gem5 全部不建模；全局所有权表等价于**零延迟的完美授予者**。
因此本实验测的是该机制在**授予策略最优极限下的性能上界**。可实现性有字面
工业先例：UPI 的 VNA（共享池 credit，接收方动态授予）+ VN0（静态保留 credit）
双结构 **[已验证: `research/iface_digest.txt`]**——工业界把"保留 vs 池"的
分界线画在与本设计**同一个位置**（VN0 静态无条件可用 ⟷ 我们的 `r`），这不是
巧合，是同一条死锁论证逼出来的，把 `r/P` 分界从设计选择升格为**被正确性约束
的必然结构**。面积可造性由 Fukase 共享 SRAM 路由器承担 **[已验证: 阶段2 事实
核查 `research/factcheck/`]**。报告中必须如此声明。

## 6. gem5 / Garnet 实现要点

基座：routing 4（自适应+逃逸），Torus3D，ctrl vnet 0（1-flit 包），阶段2
PB/PC 同款。**槽 ≡ VC、深度 1**——v1 草案的"深 VC"方案（`buffers_per_ctrl_vc
= r+P`、每-VC credit 超售、双钥匙门）**整体撤回**：深度 1 下没有超售，单枚
credit 即充分，双钥匙门自然消失。

**6.1 所有权表**：每对 `{E-in, W-in}` 一张 `PoolOwner[P]`，每项 ∈ {E, W}
（无 free 项——`U≈0`）。布局：每 IU 有 `r + P/2` 个表项，前 `r` 个是保留区
（含逃逸），后 `P/2` 个是池表项。

**6.2 三个挂点**：

- **上游门**（VC 分配）：`f` 可用 id 集 = 本侧 `r` 个保留 + `PoolOwner` 中
  归 `f` 的池 id；在其中按填充序选空闲者：**自适应保留 → 池 → 逃逸**
  （"绝不在自己私有资源闲置时消耗公共资源"——E 的保留区对 W 毫无用处，先吃
  池就是白白饿死 W）。
- **写入**：flit 写进该 id 所属的 IU（可能是对侧 IU）。
- **ST（释放=授予）**：若离开的是池槽，跑 §4.3 策略更新 `PoolOwner`。

**6.3 真实入口方向（必须）**：Garnet 在 IU 内按 `inport_dirn` 算路由。E 的
flit 存进 W-IU 后，路由器会以为它自西来 → 可能允许它掉头往东（自以为不是
U-turn）。自适应路由只选有生产性方向，实际大概率不选，**但"大概率"不是
"保证"**。修法：按**真实链路方向**算路由（flit 携 2 bit tag）。逃逸网络不
受影响（逃逸永不入池）。该 tag 一物三用：路由正确性、RTS 纯度模式、分方向
吞吐统计。

**6.4 旗标与统计**：`--dpphys-policy={rts,rr,starve}`、`--dpphys-r`、
`--dpphys-cap`；新增 `dpphys_grants_migrated`（所有权是否真的迁移过——**惰性
检查**，防"因惰性而平"被误读为"无害"）、`dpphys_pool_full_blocks`、
`dpphys_borrowed_peak`、**分方向接收吞吐**（公平性指标需要）。

**6.5 长链路**：链路延迟是 Torus3D 拓扑参数，`L ∈ {1, 8}` 给出 BDP ≈ 3 与
≈ 17+，分别落在 ¬C1 与 C1。

**待核查（实现前）**：

- **V1** flit 入队至**对侧 IU** 的可行性，以及路由计算处 inport 的注入点
  （6.3 能否干净传入真实方向）。
- **V2** crossbar 是否存在 W-IU → W-out 通路（E 源 flit 经 W-IU 西行是合法
  非 U-turn；Garnet crossbar 通常全连接、靠路由防 U-turn，需确认）。

## 7. 实验矩阵与预注册预测

4×4×4 Torus3D，vnet 0，10 000 周期，速率 0.05–1.00 步长 0.05，五模式
（xopposite、tornado、transpose、neighbor、uniform_random）。复用阶段2
harness（`research/run_sweep_physical.py` / `analyze_physical.py`），换模式表。
**`B_pair = 8`（每 IU 4 个表项）在所有模式中恒定** = 基线 `v=4` 逐槽相等。

| 模式 | 策略 | `r` | `P` | 用途 |
|---|---|---|---|---|
| PRIV | —— | —— | —— | 基线（v=4 私有） |
| RTS-a | RTS | 2 | 4 | **纯度锚点**（须 ≡ PRIV） |
| RR-a | RR | 2 | 4 | 平凡共享对照 |
| STV-a | STARVE | 2 | 4 | 贡献，稳健布局 |
| RTS-b | RTS | 1 | 6 | 纯度锚点（第二布局） |
| RR-b | RR | 1 | 6 | 平凡共享对照 |
| STV-b | STARVE | 1 | 6 | 贡献，激进布局 |

7 模式 × `L ∈ {1,8}` × 5 流量 × 20 速率 = **1400 次运行**。
（cap 剂量曲线视首批结果再加——`c` 现在管所有权，是第二轮的自由度。）

**预测（见数据前固定，阶段2 规则；赢须可复现，零结果照实报）：**

- **P1（纯度锚点）**：RTS-a、RTS-b **≡ PRIV，两个 `L`、全部 100 速率点位级
  一致**。理由：RTS 下所有权永不迁移，两种布局都退化为"1 逃逸 + 3 自适应"，
  与 PRIV 逐槽同构。**不成立则代码路径有额外副作用，先查再信任其余一切**
  （对应阶段2 的 PB6≡PB0 锚点）。
- **P2（零对照，¬C1）**：`L=1` 时所有模式 ≈ PRIV。此处出现赢说明模型有错——
  其信息量与 `L=8` 的赢等同。
- **P3（增益，C1∧C2）**：`L=8` tornado（及 transpose/uniform 的定向负载格）：
  **STV > RR ≈ PRIV**。注意 RR 也要平——RR 是静态 50/50，不该赢；**若 RR 赢
  了，收益来自服务带宽共享（§2 注）而非策略**，须据此改口径。
- **P4（侵占，C1∧¬C2）**：`L=8` xopposite：STV 出现分方向不公平和/或
  matched-load 延迟退化。若 cap 在此严格同时胜过无治理 STV 与 PRIV——那是全
  项目第一个 cap 正收益，显著报告。
- **P5（`r` 的 trade-off）**：`r=1` 布局（b）在 C1∧C2 下天花板更高
  （1.75× vs 1.5×），但在 C1∧¬C2 下退化更陡（自适应容量可归零 → 逃逸热点）。
- **P6（死锁）**：1400 次运行 0 死锁（逃逸基座按构造未动，定义 5）。

**指标**：饱和吞吐；matched-load 延迟（接受 ≥0.99、送达 ≥0.95，阶段2 定义）；
xopposite 下分方向吞吐 min/max 比（公平性）；`dpphys_grants_migrated`
（**机制启用检查**）。

## 8. 与前两阶段及先行工作的关系

**三阶段分解**：`naive 增益 = 编号效应 + 槽效应 + 约定效应`。
阶段2 固定编号与槽，测得**约定效应 = 0**。阶段1 同时变编号和槽，其增益是
未分解的混合。**变体A 固定编号总数、迁移槽的所有权**——分离出的是
**"槽 + 服务"效应**（§2 注：借来的槽由对侧读口服务，带宽一并共享），
**不是纯槽效应**，这一口径必须在报告中声明，RR 模式（P3）就是用来量它的。

顺带一个诚实的再解读：阶段1 的等承诺约定恰好是**等槽**规则（每对需 `2r+S`
槽，与配对 plain 相等，`naive-research/run_sweep_dp.py:57`）——但它未声明该
硬件、未控制编号数差异、且跑在槽通道惰性的 `L=1` 上。旧数据可作暗示引用，
不可为变体A 作证；变体A 的主张由自己的 1400 次运行承担。

**先行工作**：物理缓冲共享本身是成熟方向——DAMQ **[未验证, 经典]**、
Fukase 共享 SRAM 路由器 **[已验证]**、UBMR 的 E-W/N-S 合并省面积
**[未验证: 摘要级]**。主张因此**不是**"发明了缓冲共享"，差异化三点：

1. **贡献是授予策略，不是共享硬件**（§4.2）。先行工作把共享缓冲当**容量**
   问题（省面积）；本设计指出共享缓冲装上 RTS 策略与私有基线**逐周期恒等**，
   于是问题被重述为**策略**问题：`H_f = r + g_f`，而 `g_f` 是策略输出。
2. **共享范围 = 对向端口对，绑维度语义**——共享布在需求反相关有结构保证
   （C2）的地方，而非为省面积的全路由器合并。
3. **死锁基座保留区隔离 + 治理即研究对象**——逃逸网络整体活在永不迁移的
   保留区，安全证明零改动（定义 5），策略因此可以任意激进；cap 剂量响应、
   floor 保证、公平性指标、预注册零结果全套继承阶段2 方法论。

## 10. 符号表

| 符号 | 含义 |
|---|---|
| `B_pair` | 对向端口对的物理槽总数（= `2r + P`，恒等于基线 `2v`） |
| `r` | 每侧私有保留槽（含逃逸 VC），永不迁移 |
| `P` | 可迁移池 VC 总数（每 IU 物理承载 `P/2`） |
| `g_f(t)` | 当前授予给 `f` 侧的池 VC 数；`g_E + g_W = P` |
| `H_f(t)` | 动态落地上限 `r + g_f(t)` |
| `c` | 所有权 cap，`g_f ≤ c` |
| `floor_f(c)` | 被借到顶时的保底容量 `r + P − c` |
| `C1` | 缓冲瓶颈条件 `BDP > r + P/2` |
| `C2` | 对内需求不对称 |
| `L` | 链路延迟（gem5 中制造 C1 的旋钮） |
| RTS / RR / STARVE | 三种授予策略（§4.2–4.3） |
