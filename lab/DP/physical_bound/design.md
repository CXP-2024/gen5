## 1. 机制

固定一个路由器与一个维度，取对向输入端口对 `{E-in, W-in}`。基线每侧 `v` 条
VC、每 VC 深度 1（ctrl vnet 0 是 1-flit 包），故**一个槽就是一个 VC 表项**，
`B_pair = 2v = 8`。

| 类别 | 数量 | 物理位置 | 所有权 |
|---|---|---|---|
| 保留区 | 每侧 `r` | 本侧 IU | **永久属本侧**，含逃逸 VC |
| 共享池 | 共 `P`（每 IU 各 `P/2`） | 分布在两 IU | **可在两上游间迁移** |

`B_pair = 2r + P = 8`，与基线逐槽相等。

**共享 = 使用权迁移，不是新建共享阵列。** 池槽物理上仍属某个 IU；R 可把
W-IU 中某个池 VC 的使用权授予 E，此后 E 的 flit 写进 W-IU 该表项，并在
**W 的 SA-I 里与 W 自己的 flit 一起 round-robin**。

> **新颖点一句话**：传统 credit 语义逐字保留——单枚 credit 即充分可发、无双
> 钥匙门、无超售；**唯一的改变是池 VC 的所有权会随时间在两个上游之间迁移**。

上游只看到"我当前拥有一组可用 VC id，有 credit 就发"，**不区分 credit
类型**；类型只存在于 R 的授予器内部。

## 2. 形式定义

- **定义1（所有权）** `g_f(t)` = 授予给 `f` 侧的池 VC 数。
  **不变式 OWN**：`g_E + g_W = P`（`U ≈ 0`，见 §4.1）。
- **定义2（动态落地上限）** `H_f(t) = r + g_f(t) ∈ [r, r+P]`。
- **定义3（cap）** `c ∈ [⌈P/2⌉, P]`，强制 `g_f ≤ c`（限**所有权**，非占用）。
- **定义4（floor）** `floor_f(c) = r + (P − c)`：对向借到顶时本侧的保底容量。
- **定义5（死锁基座隔离）** 逃逸 VC 永久属本侧保留区，**绝不进入可迁移集合**。

私有基线是常数 `H_f = r + P/2`——阶段2 Corollary 1 证明任何计数器都推不动它。
**变体A 靠授予策略推动它**：`H_f` 完全由 `g_f` 决定，而 `g_f` 是策略输出。
**机制 = 策略**，硬件只让非平凡策略可表达（§4）。

**推论（策略自由）**：正确性由保留区兜底（定义5），逃逸网络的前向进展与 `g_f`
无关，**基线死锁自由证明逐字迁移**。故池策略再激进也只是性能/公平问题，
**绝不威胁正确性**。

**注（服务带宽也被共享）**：E 借走的池槽由 **W 的读口**发出，故共享的不止存储
还有服务带宽。W 闲时是白捡的，W 忙时 E 本也借不到（自限）。副作用：E 借用期间
可同拍从两个 IU 各发一个 flit，**瞬时服务率 > 1 flit/周期**。测得效应因此是
"**存储 + 服务**"而非纯槽效应，报告须按此口径声明（§7 的 RR 模式用来量它）。

## 3. 成立条件

### 3.1 C1（缓冲瓶颈）——梯度而非门

槽的回收周期 `R_slot = RTT_credit + W_R`（`W_R` = R 内部排队/仲裁等待），
链路利用率上限 `= N / R_slot`，`N = H_f`。

`RTT ≈ 2L + router_latency`：

| `L` | RTT | `N=4` 时上限 | 性质 |
|---|---|---|---|
| 1（Garnet 默认） | 3–4 | `1.14`（空载） | 只在 `W_R > 0.5` 即近饱和时受限 |
| 8（长链路档） | 17–18 | `0.24` | **空载即受限**，与负载无关 |

因此**两档增益签名不同**：

| | 机制 | 观测特征 |
|---|---|---|
| `L=8` | BDP 通道，全负载段生效 | **天花板整体抬升** |
| `L=1` | 仅近饱和受限 + SA 候选多样性 | **拐点右移，低载段重合** |

自洽性检验：深 C1 下 `(N=6)/(N=4) = 1.5` 与独立推出的天花板
`(r+P)/(r+P/2) = 6/4` 相等——C1 判据与 BDP 论证是同一件事。

（`L=8` 下 24% 利用率难看，正常设计会加缓冲；我们不能——`B_pair = 8` 被钉死
等于基线。这条等硬件纪律继承自阶段2，也是结论可信的原因。）

### 3.2 C2（对内需求不对称）

只有对向闲时才有槽可借。tornado 加热一个方向、闲置对向 = 结构性 C2；
xopposite 双向皆热 = 结构性 ¬C2。

**收益 ⟺ C1 ∧ C2；侵占暴露 ⟺ C1 ∧ ¬C2。** 两句都可证伪，矩阵在两侧布格。

### 3.3 `P` 的双向对冲

`P` 小 → C1 门槛 `r + P/2` 低 → 适用窗口更宽；但天花板 `(r+P)/(r+P/2)` 更低
（`r=1,P=6` 为 1.75×，`r=1,P=2` 仅 1.5×）。两方向相反，最优点在中间——
这个 trade-off 本身是一条结论。

## 4. 授予与归还策略（贡献所在）

### 4.1 释放时授予：`U ≈ 0`

扣在 R 手里的池 credit 对应一个谁都填不了的空槽，故**不设蓄水池**：

```
ST 周期：flit 离开池槽（R 内部事件，0 跳）
        ↓ 同周期，R 按策略决定 target ∈ {E, W}
     授予信号发出（1 跳）
```

**发送 = 释放 = 授予，同一周期、同一事件、同一处代码。** "释放→再供给"路径
为 **1 跳，与传统 credit return 完全相同**——正常路径**零额外延迟**。

**安全性自动成立**：R 只针对已确实腾空的槽发 credit，超额承诺构造上不可能，
故 v1 的 `P_eff = P−1` 陈旧性准备金**撤回**。

**Δ 的定义**：Δ = 授予环路**相对传统 credit return 的额外延迟**。正常路径
Δ=0 是物理事实；Δ=0 真正理想化掉的只有**改派**（§4.4）。

### 4.2 策略阶梯

| 策略 | `target(释放事件)` | 等价于 | 预期 |
|---|---|---|---|
| **RTS** | 给刚腾空 flit 的来源侧 | **私有基线，逐周期恒等** | ≡ PRIV |
| **RR** | 两侧交替 | —— | **< PRIV**（见下） |
| **STARVE** | §4.3 | —— | > PRIV |

RTS 一行是**恒等式不是类比**：所有权永不迁移，`g_f ≡ P/2`，`H_f ≡ r + P/2`。
且 `g_E ≡ P/2` 时 E 拥有的正是 E-IU 的全部表项 → **不存在跨 IU 写**，数据通路
也与 PRIV 逐字相同。这把性质定住：**共享阵列本身不产生收益，只是让 RTS 以外
的策略可表达。**

**RR 是反自适应的（修正 v2 的"≡ 静态 50/50"）。** 释放事件不均匀产生：只有忙
侧填满并腾空池槽，闲侧的 flit 按填充序落在自己的 `r` 里、**从不产生池释放
事件**。RR 无视状态每两次送一次给对方：

```
E 热 / W 闲，g_E=g_W=2，释放全来自 E：
  e1→E (g_E=2) · e2→W (g_E=1,g_W=3) · e3→E (g_E=1) · e4→W (g_E=0,g_W=4)
  → E 无池槽不再释放，W 闲也不释放 → 冻结
```

**单向棘轮：忙侧持续外流，闲侧从不回流**，一般情形稳态 `g` 与释放率成反比，
tornado 直接落入吸收态，`H_E = r = 2` **比 PRIV 少一半**。故 P3 改为
**`STV > PRIV > RR`**。这反而使论点更硬：策略阶梯在**两个方向**上非平凡——
中性（恒等）/ 更好 / **更差**。"贡献是授予策略而非共享硬件"由此有双侧证据。

### 4.3 STARVE 授予规则

在释放事件上求值，状态**不含**刚腾空的槽；`free_f` = `f` 拥有且空闲的槽数
（含保留区）：

```
free_E == 0 且 free_W == 0  ->  round-robin
free_E == 0                 ->  授予 E
free_W == 0                 ->  授予 W
两侧皆 > 0                  ->  round-robin
```

用 RR 而非随机：① gem5 中 RNG 会破坏 RTS≡PRIV 纯度锚点的可复现性；
② 硬件上 RR 是 1 bit，随机是一个 LFSR。

### 4.4 归还通道（承重件，非补丁）

**没有归还，STARVE 在目标场景里退化为 RTS。** 授予只在释放事件上求值，而释放
事件只由有流量的一侧产生。tornado（E 热 W 闲，`g_E=g_W=2`）：E 每次释放命中
`free_E==0` → 授予 E，`g_E` 不增长；W 轻载时 flit 全落在 `r` 里、**碰不到池
槽** → W 侧释放事件 ≈ 0 → `g_W` 冻结在 2。`H_E ≡ 4` = PRIV。

> 结构性缺陷：**迁移速率 ∝ 对向流量，迁移必要性 ∝ (1 − 对向流量)，方向相反。**

**为何必须上游发起（信息分工）**：R 有**需求信息**（`free_E/free_W` 就在它身
上）却无**安全信息**——R 不知道上游是否已把某池 VC id 承诺给一个在途 flit；
credit 无拒收，强行收回 = 该 flit 无处落地。R 主动收回需 revoke→ack 的 **2 跳
往返**；上游自己发起是 **1 跳单向**，因为只有它知道自己有没有承诺出去。
**需求判断留在 R，安全判断留在上游。**

**触发条件用瞬时余量，不用空闲计时**：

```
credits_held > flits_queued
```

"连续 T 周期没发 flit"是坏检测器——C1 区里被 credit 饿住的一侧大部分周期也
发不出 flit，会在最饥饿时把 credit 交出去。余量条件下被饿住的一侧
`credits_held = 0`，**永不触发**。

**两级阶梯**（自变量是"是不是最后一枚"，不是持有量）：

| `g_f` | `T` | `L=8` | 理由 |
|---|---|---|---|
| `≥ 2` | `RTT/4` | ≈4 | 纯余量，尽快让出 |
| `= 1` | `2·RTT` | ≈34 | 唤醒保险，可以等等 |

任一周期 `flits_queued ≥ credits_held` → 计时器清零。归还 1 枚/次，指名 VC id
（`⌈log2 P⌉+1` bit 边带，与数据同向，不新增反向线）；R 把它当作一次**合成释放
事件**跑同一套 STARVE 规则（`U` 仍恒为 0，只有一条代码路径），被判回则退避。

**边际价值在 `2→1` 反号**（深 C1 下吞吐 ∝ 槽数，百分比即吞吐百分比）：

| 交出 | 对向 | 自己 |
|---|---|---|
| `2→1` | `H` 4→5，**+25%** | `H` 4→3，**−25%** |
| `1→0` | `H` 5→6，**+20%** | `H` 3→2，**−33%** |

反号来自分母：对向已有 3 枚，第 4 枚边际递减；我只剩 1 枚，它是**从 `r` 到
`r+1`** 的那枚——`g=0` 时本侧只剩 1 逃逸 + 1 自适应，正是 §5.2 的塌方悬崖。
**最后一枚是唤醒保险，不是余量。**

**定义域是 `{2, 1}`，不需要 `T(3)`**：`g ≥ 3` 要求在 `g=2` 时再获授予，而授予
前提是 `free_f == 0`（满载），满载侧不跑归还（余量条件不成立）；等它闲下来，
排空过程本身就是 3 次池释放事件，STARVE 会自动把盈余还回去。tornado 中轻载侧
更是从 `g=2` 单向下行 `2→1→0`。残留边角（授予刚到流量就停，槽从未被填过、无
释放事件）数量有界，被上表的 `≥2` 行覆盖。**RR 若把某侧顶到 4，同表也已覆盖。**

**RTS 模式禁用归还**：归还是无 flit 的合成释放事件，**没有 sender**，RTS 规则
在此无输入；任何补丁都会破坏 P1 要求的位级一致。

**让出慢、收回快**：归还由自身空闲计数驱动（慢），重获由对向释放事件驱动
（快）。W 唤醒时先用 `r` 顶住瞬态，`free_W` 归零后 E 满载 → 释放密集 → STARVE
每次命中 `free_W==0` → 立刻拿回。正因收回快，`T(≥2)` 可以取得激进。

**首批 RR 不开归还通道**：余量条件本身是需求信号，接到 RR 上会污染对照组。
三模式因此在同一自变量上排开：

| 模式 | 授予 | 归还 | 需求信息 | 预测 |
|---|---|---|---|---|
| RTS | 无 | 关 | 零 | ≡ PRIV（恒等） |
| RR | 无 | 关 | 零，盲目再分配 | **< PRIV** |
| STARVE | 有 | 开 | 全 | > PRIV |

可选第二批 **RR+return**（RR 授予 + 需求驱动归还）拆开"收益来自授予侧还是归还
侧"——全项目的核心问题，也堵住"对照组被阉割"的质疑。

## 5. 代价

### 5.1 端口：读口免费，写口要钱

**读口零增量，且不靠仲裁而是构造上无冲突**：每个池槽物理属唯一 IU，W-half 的
槽只可能被 W 的 SA-I 选中；每 IU 仍每周期读 1 个 VC。

> 附带证伪：**靠 RR 指针相位错开来避开池端口争用不成立。** `r=2,P=4` 时每侧有
> 2/3 时间落在池上，鸽笼给出重叠 ≥ 1/3，任何偏移都消不掉；且 RR 的可选集由流量
> 决定，相位不可控。强制交替令牌能保证，但把这一对的池读带宽钳死在 1
> flit/周期 → **约 50% 带宽损失**。正确解是静态槽→端口绑定：不靠指针在时间上
> 错开（概率性），而靠槽在空间上归属唯一端口（确定性）。

**写口是主要代价，且牵涉无损性**：每周期最多 2 个到达，**只有落在同一 IU 时才
冲突**（`(E→W-half, W→W-half)` 撞；`(E→E-half, W→W-half)` 不撞）。credit 流控
**无拒收**，输的 flit 无处可去也不能丢，故必须**保证**而非临场仲裁：

- **(a) 池区双写口**（首批取此）：每 IU = 1W（本链路）+ 1W（跨接通路），读仍
  1R；**保留区不受影响**（永不接收跨写），2W 只加在 `P/2` 个池表项上。
- **(b) 授予侧纪律**：策略保证不出现同拍同 IU 双写。STARVE 下天然罕见，但
  "罕见"不是"保证"，**不足以承担无损性**。

**走线**：跨接通路比贴身私有缓冲长，高频下有时序压力
**[未验证: 与 Fukase 共享 SRAM 路由器同类问题]**。

### 5.2 干扰与 `r` 的划分

无治理（`c=P`）时对向可借空池，`f` 从 `r+P/2` 跌到 `r`——方向间不公平与
matched-load 延迟退化是预期现象（经典 DAMQ hogging）。cap 是治理旋钮但**治理
有价**：floor 每抬 1 槽，可借上限降 1 槽；`c = P/2` 是零退化零收益的中性点。

`r` 的内部划分是同一 trade-off 的具体形态：

- **`r=1`（纯逃逸）**：`P` 最大、天花板最高（1.75×）。风险实在：池被借空时本侧
  自适应容量归零，**全部流量挤进 DOR 受限的逃逸 VC** → 热点塌方。
- **`r=2`（1 逃逸 + 1 自适应保留）**：保底 1 个自适应槽，退化平缓；`P` 少 2。

**`T(1)` 使这条划分从编译期常数变为流量自适应的连续旋钮**：`T(1)=∞` 等价于
"最后一枚永不归还" = 静态 `r=3, P=2`（天花板降到 1.25×，唤醒瞬态最平缓）；
`T(1)` 小则逼近 `r=2, P=4` 的激进配置。闲得久滑向激进，一有需求弹回保守。

### 5.3 适用域与复杂度

- **窄适用域**：C1 在 1 周期链路的普通 mesh 里弱，那里部署=只付账不收益。机制
  该用于长 credit 环 / 极小缓冲（chiplet、D2D、长片上互连），与
  `permission_domain/` §3 的 PS1 域重合。这是设计结论，不是遗憾。
- **正确性负担**：私有缓冲的隔离物理免费；迁移后定义5 要靠分配逻辑保证。
- **真实入口方向须显式携带**——但仅服务于 credit 转向与分方向统计，
  **非路由正确性需求**（v4 核查，§6.5）。

### 5.4 gem5 定位

5.1–5.3 的硬件项 gem5 全部不建模；全局所有权表 = 零延迟完美授予者。故本实验测
的是**授予策略最优极限下的性能上界**。工业先例：UPI 的 VNA（共享池 credit，
接收方动态授予）+ VN0（静态保留 credit）**[已验证: `research/iface_digest.txt`]**
——工业界把"保留 vs 池"的界线画在与本设计**同一位置**，是同一条死锁论证逼出来
的，把 `r/P` 从设计选择升格为**被正确性约束的必然结构**。面积可造性由 Fukase
共享 SRAM 路由器承担 **[已验证: `research/factcheck/`]**。报告须如此声明。

## 6. gem5 / Garnet 实现要点

基座：routing 4（自适应+逃逸），Torus3D 4×4×4，ctrl vnet 0，阶段2 PB/PC 同款。
**槽 ≡ VC、深度 1**——v1 的"深 VC"方案（`buffers_per_ctrl_vc = r+P`、每-VC
credit 超售、双钥匙门）**整体撤回**：深度 1 下无超售，单枚 credit 即充分。

本节 v4 依据 **2026-09-06 源码核查**（`~/gem5` @ `db57aab`）重写：6.1 与 6.2 是
核查新发现的**前置阻塞点**，6.6 由"必须"降级，末尾给出 V1/V2 判定。

### 6.1 编号空间（前置阻塞点 A）

Garnet 中 `InputUnit::virtualChannels[vc]` 与上游 `OutputUnit::outVcState[vc]`
共用**每条链路各自的 `0..V-1`** 空间，一一对应。因此 **E 的编号空间里不存在任何
id 能指向 W-IU 的表项**：E 只有 `v=4` 个 id，全部映射到 E-IU 自己的 4 项，
`H_E` 无法取到 `r+P=6`。**当前形态在 Garnet 中不可表达**，`PoolOwner` 无落脚点。

修法：给端口对一个**全局编号空间** `vcs_per_vnet = 2r + P = 8`，静态映射 id→IU
（`0,1`=E 保留，`2,3`=W 保留，`4,5`=E-IU 池项，`6,7`=W-IU 池项），所有权只决定
**谁可用哪些 id**，不改 id 的物理归属。三个连带后果必须在报告中明说：

- **等硬件从"数组大小保证"降级为"掩码 + 断言保证"**：每 IU 会实例化 8 个
  `VirtualChannel`（对内 16），合法仅 8。须加 per-IU 占用 `≤ r + P/2` 的运行时
  断言（`gem5_assert`），并在报告里声明这是**全项目地基**。
- **`select_free_vc` 须掩码化**：现有 `OutputUnit::select_free_vc(vnet,
  first_offset, count)` / `free_vc_credit_count(...)` 是**连续窗口**式，而 E 的
  可用集 `{0,1} ∪ (granted ⊆ {4..7})` 不连续，需新增按位掩码版本。
- **Local 口会被误伤并直接打穿 P1**：`vcs_per_vnet` 是全网参数，NI/Local 口也会
  拿到 8 条 VC → 注入缓冲比 PRIV 翻倍 → **RTS ≡ PRIV 必然失败**。须把 Local 口
  可用 id 静态钉死为基线那 `v=4` 个。

### 6.2 逃逸 VC 谓词化（前置阻塞点 B）

现有代码以"**最高 `escape_vcs` 个 id**"约定标识逃逸 VC
（`invc % vcs_per_vnet >= vcs_per_vnet - escape_vcs`），共 9 处：
`RoutingUnit.cc:392,507`、`SwitchAllocator.cc:152,256,480,599`、
`NetworkInterface.cc:463`、`GarnetNetwork.cc:196,372`。

新布局下逃逸槽必须常驻**各侧保留区**（定义5），不可能同时是共享 8-id 空间的
最高位。须先抽成谓词 `isEscapeVC(vc)` / `escapeWindow(side)`。该重构机械但
**必须前置**，且自带验收标准：**重构后 PRIV 须与重构前逐位一致**——这正是 P1
的地基，独立成一个低风险 commit。

### 6.3 所有权表

每对一张 `PoolOwner[P]`，每项 ∈ {E, W}（无 free 项）。每 IU 物理承载 `P/2` 项，
本侧前 `r` 项为保留区（含逃逸）。

### 6.4 四个挂点（均已在源码中定位）

| 挂点 | 位置 | 状态 |
|---|---|---|
| ① 上游门（VC 分配） | `SwitchAllocator::vc_allocate` + `OutputUnit::select_free_vc` | 需掩码版（6.1） |
| ② 写入（跨 IU 落槽） | `InputUnit::wakeup` → 新增 `depositFlit(vc, flit)` | 可行，见 V1 |
| ③ ST（释放=授予） | `SwitchAllocator::arbitrate_outports` 的 3 处 `increment_credit` | 与 §4.1 逐字对上 |
| ④ 归还 | 上游侧计时器 + R 侧合成释放事件 | 复用 `Credit`（Q6 已定） |

填充序 **自适应保留 → 池 → 逃逸**（绝不在私有资源闲置时消耗公共资源——E 的保留
区对 W 毫无用处）。挂点③ 落在 `arbitrate_outports`：**发送 = 释放 = 授予、同一
处代码**，即"授予"仅是选择调用哪一侧 IU 的 `increment_credit`。

### 6.5 真实入口方向（**降级**：非路由正确性需求）

v3 称此项为路由正确性"必须"，**核查后撤回**：`RoutingUnit::outportCompute3DAdaptive`
（`RoutingUnit.cc:382`）**根本不读 inport**——它只用 `current_id`/`dest_id` 算最
小方向集、再按 credit 计数选路，routing 4 下掉头**按构造不可能**；`InputUnit`
里那次 `route_compute` 会被 SA 覆盖。2 bit tag 仍需保留，但用途缩为
**credit 转向 + 分方向吞吐统计（公平性指标）**。

### 6.6 旗标与统计

`--dpphys-policy={rts,rr,starve}`、`--dpphys-r`、`--dpphys-cap`、
`--dpphys-return-base`（`T(≥2)`）、`--dpphys-return-t1`；统计
`dpphys_grants_migrated`、`dpphys_credits_returned`（二者共同构成**机制真的启用
了**的惰性检查）、`dpphys_pool_full_blocks`、`dpphys_borrowed_peak`、
**分方向接收吞吐**。

### 6.7 长链路

链路延迟已是 Torus3D 参数（`configs/topologies/Torus3D.py:54` 取
`options.link_latency`），`L ∈ {1, 8}` **仅需命令行开关，零代码改动**。

### 6.8 核查判定（V1/V2 已闭合）

- **V2 通过，零改动。** `CrossbarSwitch::wakeup()` 直接
  `m_router->getOutputUnit(t_flit->get_outport())->insert_flit(t_flit)`，
  **全连接、无 `inport != outport` 限制**，W-IU → W-out 通路本就存在；防掉头只
  存在于路由函数中。
- **V1 通过，改动小。** `InputUnit::wakeup()` 持有 `m_router`，
  `Router::getInputUnit()` 存在，`insertFlit / set_vc_active / grant_outport`
  均为 public；`virtualChannels` 私有且无跨 IU 访问器，故新增一个
  `depositFlit(vc, flit)` 访问器并接管 buffer-write 统计即可。

### 6.9 与旧 DP 代码的关系

阶段1/2 的 `dp_governs / dp_cbs_admission / dpNoteAlloc / dpNoteFree` 及 CBS 标记
已深嵌 `SwitchAllocator::vc_allocate` 与 `OutputUnit::wakeup`
（`GarnetNetwork.cc` 16 处、`SwitchAllocator.cc` 22 处等）。DP-Phys 是**另一个
机制**：旧 DP 代码**整体移除后重写**，不复用、不并存——复用会让两个机制互相
污染，P1 也讲不清。

## 7. 实验矩阵与预注册预测

4×4×4 Torus3D，vnet 0，10 000 周期，速率 0.05–1.00 步长 0.05，五模式
（xopposite、tornado、transpose、neighbor、uniform_random）。复用阶段2 harness
（`research/run_sweep_physical.py` / `analyze_physical.py`）。
**`B_pair = 8` 在所有模式中恒定** = 基线 `v=4` 逐槽相等。

| 模式 | 策略 | 归还 | `r` | `P` | 用途 |
|---|---|---|---|---|---|
| PRIV | —— | —— | —— | —— | 基线（v=4 私有） |
| RTS-a | RTS | 关 | 2 | 4 | **纯度锚点**（须 ≡ PRIV） |
| RR-a | RR | 关 | 2 | 4 | 反自适应对照 |
| STV-a | STARVE | 开 | 2 | 4 | 贡献，稳健布局 |
| RTS-b | RTS | 关 | 1 | 6 | 纯度锚点（第二布局） |
| RR-b | RR | 关 | 1 | 6 | 反自适应对照 |
| STV-b | STARVE | 开 | 1 | 6 | 贡献，激进布局 |

7 模式 × `L ∈ {1,8}` × 5 流量 × 20 速率 = **1400 次运行**。

**预测（见数据前固定；赢须可复现，零结果照实报）：**

- **P1（纯度锚点）** RTS-a/RTS-b **≡ PRIV，两个 `L`、全部 100 速率点位级一致**
  （RTS 下所有权不迁移、无跨 IU 写）。不成立则代码有额外副作用，**先查再信任
  其余一切**。这是丢掉 `L=1` 零对照后**唯一**的纯度锚点，但它是恒等式而非预测。
- **P2′（梯度，替换 v2 的零对照 P2）** `gain(L=8) ≫ gain(L=1) > 0`，且 `L=1` 的
  收益**只出现在近饱和段、低载段必须重合**。低载段就分离 ⇒ 有 RTT 之外的副作用
  （多半是 §2 注的服务带宽共享），归因错误。
- **P3（策略双侧非平凡）** `L=8` tornado（及 transpose/uniform 的定向格）：
  **STV > PRIV > RR**。RR 若不劣于 PRIV，则 §4.2 的棘轮推导有误。
- **P4（侵占，C1∧¬C2）** `L=8` xopposite：STV 出现分方向不公平和/或
  matched-load 延迟退化。若 cap 在此严格同时胜过无治理 STV 与 PRIV——那是全项目
  第一个 cap 正收益，显著报告。
- **P5（`r` 与 `T(1)` 的 trade-off）** 布局 b 在 C1∧C2 下天花板更高
  （1.75× vs 1.5×），在 C1∧¬C2 下退化更陡。附敏感性：
  `T(1) ∈ {RTT, 2·RTT, 4·RTT, ∞}`，其中 **`T(1)=∞` 应与静态 `r=3,P=2` 位级
  一致——第二个免费纯度锚点**。
- **P6（死锁）** 1400 次运行 0 死锁（逃逸基座按构造未动，定义5）。

**指标**：饱和吞吐；**饱和拐点位置**（P2′ 的 `L=1` 支需要）；matched-load 延迟
（接受 ≥0.99、送达 ≥0.95，阶段2 定义）；xopposite 分方向吞吐 min/max 比；
`dpphys_grants_migrated` + `dpphys_credits_returned`（机制启用检查）。

## 8. 与前两阶段及先行工作的关系

**三阶段分解**：`naive 增益 = 编号效应 + 槽效应 + 约定效应`。阶段2 固定编号与
槽，测得**约定效应 = 0**；阶段1 同时变编号和槽，其增益是未分解的混合。变体A
固定编号总数、迁移槽的所有权，分离出的是**"槽 + 服务"效应**（§2 注），
**不是纯槽效应**，报告须声明。

阶段1 的等承诺约定恰好是**等槽**规则（`naive-research/run_sweep_dp.py:57`），
但它未声明该硬件、未控制编号数差异、且跑在 `L=1` 上。旧数据可作暗示引用，
**不可为变体A 作证**；变体A 的主张由自己的 1400 次运行承担。

**先行工作**：DAMQ **[未验证, 经典]**、Fukase 共享 SRAM 路由器 **[已验证]**、
UBMR 的 E-W/N-S 合并省面积 **[未验证: 摘要级]**。主张**不是**"发明了缓冲共享"，
差异化三点：

1. **贡献是授予策略，不是共享硬件。** 先行工作把共享缓冲当**容量**问题（省
   面积）；本设计指出共享缓冲装上 RTS 与私有基线**逐周期恒等**、装上 RR 甚至
   **劣于**私有基线（§4.2），于是问题被重述为**策略**问题：`H_f = r + g_f`。
2. **共享范围 = 对向端口对，绑维度语义**——布在需求反相关有结构保证（C2）的
   地方，而非为省面积的全路由器合并。
3. **死锁基座隔离 + 治理即研究对象**——逃逸网络整体活在永不迁移的保留区（定义
   5），安全证明零改动，策略因此可任意激进；cap 剂量响应、floor 保证、公平性
   指标、预注册零结果全套继承阶段2 方法论。

## 10. 符号表

| 符号 | 含义 |
|---|---|
| `B_pair` | 端口对物理槽总数（`2r + P`，恒等于基线 `2v = 8`） |
| `r` | 每侧私有保留槽（含逃逸 VC），永不迁移 |
| `P` | 可迁移池 VC 总数（每 IU 物理承载 `P/2`） |
| `g_f(t)` | 授予给 `f` 侧的池 VC 数；`g_E + g_W = P` |
| `H_f(t)` | 动态落地上限 `r + g_f(t)` |
| `c` / `floor_f(c)` | 所有权 cap `g_f ≤ c` / 保底容量 `r + P − c` |
| `R_slot` | 槽回收周期 `RTT_credit + W_R` |
| `T(g)` | 归还阈值：`g≥2` 为 `RTT/4`，`g=1` 为 `2·RTT` |
| `C1` / `C2` | 缓冲瓶颈（梯度，§3.1）/ 对内需求不对称 |
| `L` | 链路延迟（制造 C1 的旋钮），`RTT ≈ 2L + 1` |
| RTS / RR / STARVE | 三种授予策略（§4.2–4.4） |
