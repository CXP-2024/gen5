Parity removes cross-direction Pool-read conflicts; ordinary VC/switch arbitration remains inside the selected bank.

Read side

At most one pooled flit from the pair enters switch allocation per cycle. It uses the crossbar port of its true ingress — the shared datapath needs no extra lane.

Write side

A per-pair write guard admits at most one adaptive flit into the Pool each cycle. The other arrival may use its RES when a reserved credit is free; otherwise it waits.

The phase tax

A hot side is served by the Pool only every other cycle, and a cold side's unused phases are not work-conserving.

This is the +2~3% latency visible under balanced traffic — the price the skew win must repay.

Equal buffers, 1R1W Pool. Area and energy still require RTL synthesis of owner state, selectors, and wiring.

Blocked adaptive packet → always drains via ESC, routed in deterministic XYZ order

escape never takes wrap-around links — a deadlock-free subnetwork whose storage never moves

Phase discipline holds under any policy

The complementary schedule is deterministic parity — whoever owns the slots, only one direction touches the Pool per cycle, and every bank is examined every other cycle: service is delayed, never denied. Measured: 0 read conflicts in all 651 runs.

The pool cannot break escape

Migration reshuffles only the 4 pool slots. RES — private + escape — is physically excluded, so the non-wrapping escape network stays intact under any ownership state.

Any grant policy is safe by construction — aggressiveness is a performance question, never a correctness question.

Pool-Credit Grant: Pressure — the Credit Follows Demand

On every pool release, who gets the freed credit?

release → side with the fuller RES  ·  tie → last owner keeps it (sticky)

Credit = ownership

Holding a pool slot's credit = the right to land one flit there. Granting is migration — no owner table broadcast.

Blind owner-RR parks credits on the idle side — tornado L=8: 0.435× throughput · 3.181× latency.

Owner cap 3

The hot side owns at most 3 of 4 pool credits — the peer always keeps one. Cap 4 is reported only as a full-elasticity upper bound.

own_E + own_W = 4 — credits conserved, one owner per slot, each side ≤ cap.

Implementation · 3 / 3

On-Demand Reclaim: An Idle Peer Credit Never Blocks You

Allocation-time reclaim · owner table flips in the same cycle

allocate: RES → owned pool → reclaim idle peer slot → escape

Why release-grants alone freeze

An idle side releases nothing — no release event exists to move its credits. Reclaim acts at allocation time, exactly when demand appears.

Reclaim condition — never revokes

peer slot idle ∧ requester < cap 3. A busy slot is never touched — an in-flight flit keeps its promised space.

Instrumented validation run (tornado L=8): ≈0.5% of pool allocations trigger a reclaim — mobility on demand, stability otherwise.

Zero-delay caveat

The owner-table flip is modeled at 0 cycles. Reported gains are an optimistic upper bound until a one-cycle grant wire is added.

Why it works

Flows stay distributed across X rings, so the private design stalls on input credits first. One borrowed cold-side slot lifts that limit before the output link saturates.

Scale ablation · 6 & 8 VCs

More private VCs push the crossover to higher load — but near each new knee the pool again extends the stable range (6 VC: 0.12 → 0.15). Sharing is a near-saturation tool at every scale.

Evaluation · 3 / 3

Where Tidal Helps — and Where the Phase Tax Wins

Best case

Persistent one-direction pressure

  • X-biased 90/10: latency −9.2% at equal storage.
  • 100% +X: 1.818× delivered throughput above private saturation.
  • Long credit loop (L=8): borrowing has time to matter.
Small win

Tornado under high load

  • L=8 link latency · 1-flit packets · inj 0.9.
  • Latency 49.37 → 46.97 cycles: −4.85%.
  • Throughput unchanged — an output bottleneck caps the gain.
  • Cap 3 captures ~83% of the cap-4 benefit while borrowing only 1 slot.
No advantage

Balanced or fast-changing demand

  • Uniform L=8: latency +3.2% at inj 0.9.
  • X-opposite: both sides fight for one pool, +3~15%.
  • Short links (L=1): tornado +25.1% — no credit-loop slack to reclaim.
  • Reversal every 16 cycles: +7.8% — ownership churns while old traffic drains.
Honest read: Tidal is a specialization for sustained directional skew — not a universal replacement for private buffers. All gains assume the zero-delay owner grant; a one-cycle grant wire is the next experiment.
