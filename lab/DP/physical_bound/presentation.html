Motivation: Two Structural Problems

Problem 1 — C1

Credit round-trip caps throughput

A buffer slot is unusable while its credit is in flight:

throughput ceiling = N / R_slot, R_slot ≈ RTT + queueing, RTT ≈ 2L + 1
Link latencyRTTCeiling (N=4)
L = 1 (default)3–4 cy> 1 — limited only near saturation
L = 8 (long link)17–18 cy0.24 — limited even when idle

Long links (chiplet / D2D) make buffers the bottleneck at every load. The textbook fix is more buffers — that costs area. We add zero slots.

Problem 2 — C2

Directional demand asymmetry

Tornado-like traffic heats one direction and leaves the opposite idle:

With private buffers this waste is structural: no policy can move a slot across the wall.

Question: can the busy side borrow the idle side's slots — without adding hardware, without touching deadlock freedom?

Equal physical budget B_pair = 2v = 8 — we migrate ownership, not capacity.

  • Reserved r=2 per side (incl. escape VC) — owned permanently, never migrates
  • Pool P=4 — each slot physically stays in its IU, but its ownership (which upstream may use it) migrates E ⇄ W

Credit Semantics Untouched

Upstream still sees only "my usable VC ids + credits" — one credit = free to send, no double-key gate, no oversubscription. The only change: pool ownership moves over time.

Why It Helps — the Intuition

The busy side's landing capacity becomes dynamic:

H_f = r + g_f ∈ [r, r+P] private baseline: H_f ≡ r + P/2 (constant)

In the C1 regime throughput ∝ slots, so shifting all pool slots to the hot side lifts its ceiling:

(r+P) / (r+P/2) = 6/4 = 1.5×
  • Self-limiting: idle side's slots are only borrowable because it is idle — when it wakes up, its own traffic reclaims them
  • Service bandwidth comes along: a borrowed slot is drained by the host IU's read port — the pair can momentarily send 2 flits/cycle
  • Sharing scope = dimension pair, exactly where tornado-class traffic guarantees anti-correlated demand (C2)

Implementation ① — Safety: Three Layers of Deadlock Freedom

Layer 1 — Escape VC

Adaptive routing may pick any minimal direction; one VC class per vnet is the escape class, routed by deterministic dimension-order (XYZ) routing. Any blocked packet can always fall into the escape network → the adaptive layer can never create a cycle that matters.

Layer 2 — CBS (Critical Bubble Scheme)

Torus wrap-around rings can still deadlock under DOR. CBS marks one critical bubble per directed ring: packets entering the ring may never consume the marked free slot; in-ring packets displace it upstream. The ring can never completely fill → no ring deadlock.

Layer 3 — Credit Reservation (DP-Phys)

The escape VC lives in the reserved region — permanently owned, excluded from the migratable pool by construction. Migration can rearrange pool ownership arbitrarily; the escape network never notices.

Why the Proof Transfers Verbatim

  • Baseline deadlock-freedom = escape VC (layer 1) + CBS (layer 2), proven before DP-Phys exists
  • DP-Phys touches only pool slots; reserved slots (incl. escape) keep owner, position, and credit path unchanged
  • Forward progress of the escape network is independent of g_f — any grant policy, however aggressive, is a performance question, never a correctness question
Invariants enforced at runtime: g_E + g_W == P (no credit lost/created) per-IU active VCs ≤ r+P/2 (equal hardware) B_pair == 8 constant (equal budget) Local port pinned to v=4 (no hidden buffer)

These invariants are the acceptance gate for every milestone — if any fires, the data is discarded.

Implementation ② — Credit Grant Policy

Grant = Release = Send

When a flit leaves a pool slot, the router decides in the same cycle which upstream receives the freed credit. The credit itself carries ownership — no broadcast, no shared table for safety:

pool slot x owned by side f ⟺ x's credit is held by f's upstream

Normal path adds zero latency vs. a traditional credit return (same 1-hop signal). Safety is automatic: the router only grants slots that are genuinely empty.

STARVE — demand-aware grant
free_E==0 ∧ free_W==0 → round-robin free_E==0 → grant E free_W==0 → grant W both free → round-robin

free_f = slots side f owns and has empty. Grant chases starvation.

RR — the deliberate control arm

Blind alternation, zero demand information. Analysis predicts a one-way ratchet:

E hot / W idle, g_E = g_W = 2: releases come only from E's slots → every 2nd grant leaks to idle W → g_E → 0, frozen; H_E = r only

Busy side bleeds out, idle side never releases → never gives back. Prediction: RR < PRIV.

Why Keep a Bad Policy?

Three arms on the same shared hardware:

If both predictions hold, the gain is attributable to the grant policy, not to the shared hardware — two-sided evidence.

Implementation ③ — Credit Return Policy

Why Grants Alone Are Not Enough

Grants fire only on release events — and releases only come from the side that has traffic:

tornado: E hot, W idle, g = 2/2 E releases → free_E==0 → grant back to E W's few flits fit in reserved r → W's pool slots never release → ownership frozen at 50/50 forever

Migration rate ∝ opposing traffic; migration necessity ∝ (1 − opposing traffic). The directions are opposite — a structural defect that only an upstream-initiated return channel can fix.

Who Initiates — Information Split

Router knows demand but not safety (whether upstream promised a credit to an in-flight flit). Upstream knows safety. So the holder returns voluntarily: 1-hop, no revoke/ack round-trip.

Trigger: Surplus, Not Idleness

credits_held > flits_queued (sustained for T cycles)

"Idle for T cycles" is a broken detector — a starving side also sends nothing, and would surrender credits at its hungriest. Under the surplus rule the starving side holds 0 credits and never triggers.

Transport: returned credit rides the existing reverse credit link (1 extra flag bit, zero new wires) and is treated by the router as a synthetic release event — same grant rule, one code path.

Discussion: Novelty & Limitations

Novelty

  • Policy, not hardware. Prior shared-buffer work (DAMQ, shared-SRAM routers) saves area — a capacity story. We fix the budget (B_pair = 2v, zero extra slots) and show the grant policy alone decides whether you beat or lose to a private baseline — with RR and STARVE bracketing PRIV from both sides on identical silicon.
  • Opposing-port scope, bound to dimension semantics. Sharing is placed exactly where torus traffic guarantees anti-correlated demand (C2) — not a whole-router merge for area's sake.
  • Deadlock base fully isolated. Escape VCs live in the never-migrating reserved region — safety proof transfers verbatim, so the policy layer is free to be aggressive. (Same reserved/pool split as Intel UPI's VN0/VNA credits.)

Limitations

  • Pool slots need 2W1R. Two same-cycle arrivals can land in one IU (own link + cross-path), and credit flow control cannot reject — the pool region needs a second write port. Reads stay 1R: each slot is drained only by its host IU's allocator (static slot→port binding). Reserved region unaffected.
  • Return traffic rides the credit network. Returned credits borrow the reverse credit link; a 1-bit flag and demultiplexing at both ends. Transient by design (return domain is g ∈ {2,1}), but contention is measured and reported, not assumed away.
  • gem5 models none of the circuit costs (write port, wiring, timing). Results are an upper bound under an idealized zero-latency grant unit.
  • Narrow applicability by design. C1 is weak on 1-cycle-link meshes — the mechanism targets long credit loops / tiny buffers (chiplet, D2D). Deploying it elsewhere pays the cost without the gain.
